# v0.2 Plan — Native Hermes Plugin / MCP for Theta EdgeCloud

## Goal

Turn the v0.1 Theta EdgeCloud Hermes skill + helper script into a native integration that exposes first-class Theta tools to Hermes users while preserving the v0.1 security model: command-scoped credentials, redacted output, dry-run safety, and explicit confirmation for paid/mutating operations.

## Recommended architecture

Build both layers, in this order:

1. **MCP server first** — portable across Hermes and other MCP-capable agents.
2. **Hermes plugin/toolset wrapper second** — best UX for Hermes users, with native `theta_*` tools and check functions.

This keeps the core Theta client reusable and avoids duplicating API logic.

## Credential model

Each tool should declare the minimum required env vars:

- Controller/project tools: `THETA_EC_API_KEY`, `THETA_EC_PROJECT_ID`
- Balance: `THETA_EC_API_KEY`, `THETA_ORG_ID`
- On-demand: one of `THETA_ONDEMAND_API_TOKEN`, `THETA_ONDEMAND_API_KEY`, `THETA_API_KEY`
- Dedicated endpoint: `THETA_INFERENCE_ENDPOINT` plus token or Basic Auth pair
- Video: `THETA_VIDEO_SA_ID`, `THETA_VIDEO_SA_SECRET`

Hermes plugin check functions should only expose tools when their credential group is configured.

## Safety requirements

- Redact sensitive keys recursively in every tool response.
- Never echo raw request headers, auth values, endpoint auth passwords, registry passwords, or env var secret values.
- Require `dry_run=true` or `confirmed=true` for deployment create/delete/stop/start.
- Require `confirmed=true` or a cost note for paid on-demand media generation and dedicated deployment creation.
- Enforce `https://` for dedicated endpoint auth calls.
- Include timeout and max-poll controls for long warm-ups.
- Return structured error objects instead of raising raw exceptions.

## Dedicated endpoint workflow

Implement a safe disposable validation tool:

1. Read current org balance.
2. List templates and VM catalog.
3. Select template/VM explicitly from user input; do not auto-pick expensive GPUs without confirmation.
4. Generate Basic Auth credentials in memory.
5. Create deployment.
6. Poll readiness using template-specific probes:
   - vLLM/OpenAI templates: `/v1/models`
   - Gradio templates: `/config`
7. Run one smoke request.
8. Delete deployment in `finally`.
9. Verify deployment list is empty.
10. Report balance delta.

## Testing plan

- Unit tests for redaction of nested payloads and HTTP error bodies.
- Unit tests for dry-run validation and target validation.
- Schema tests for every native tool.
- Mocked HTTP tests for `404 -> 503 -> 500 -> 200` warm-up sequences.
- Live tests gated by env var, never run by default.
- Release test: install in clean Hermes profile, verify skill/tool discovery.
