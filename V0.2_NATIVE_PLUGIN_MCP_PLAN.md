# v0.2 Plan — Hermes Integration for Theta Official MCP + Extensions

## Revised direction

Theta Labs now publishes an official MCP server for Theta EdgeCloud On-Demand Model APIs:

- npm: `@thetalabs/on-demand-api-mcp`
- GitHub: `https://github.com/thetalabs/on-demand-api-mcp`
- Checked npm version: `0.1.7`
- Runtime: Node.js `>=18`
- License: MIT

So v0.2 should **not duplicate the official on-demand MCP server**. Instead, v0.2 should make this repository the Hermes-first integration layer around Theta's official MCP server, plus add missing Hermes/controller/dedicated deployment workflows.

## v0.2 goal

Provide the easiest, safest path for Hermes users to use Theta EdgeCloud:

1. Configure Theta's official on-demand MCP server in Hermes.
2. Use the official MCP tools for on-demand inference.
3. Keep this skill/helper for controller APIs, org balance, dedicated endpoints, deployment lifecycle, safety wrappers, and Hermes-native UX.
4. Optionally add a Hermes plugin/toolset that registers direct `theta_*` tools later.

## What the official MCP server covers

Per Theta's announcement, the official MCP server exposes:

- `list_services` — discover available on-demand AI models and capabilities.
- `infer` — run inference on on-demand models.
- `get_request_status` — poll async inference jobs.
- `get_upload_url` — get presigned upload URLs for file inputs.

In Hermes these should appear with the configured MCP server prefix, for example:

- `mcp_theta_ondemand_list_services`
- `mcp_theta_ondemand_infer`
- `mcp_theta_ondemand_get_request_status`
- `mcp_theta_ondemand_get_upload_url`

## Hermes MCP config

Add this to `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  theta_ondemand:
    command: "npx"
    args: ["-y", "@thetalabs/on-demand-api-mcp"]
    env:
      THETA_API_KEY: "${THETA_ONDEMAND_API_TOKEN}"
    timeout: 180
    connect_timeout: 60
```

Notes:

- Hermes passes only a filtered environment to MCP subprocesses plus values explicitly listed in `env`.
- Prefer storing the real token in `~/.hermes/.env`, then referencing it in config if Hermes supports interpolation in the active version. If interpolation is not available, put the token directly in `config.yaml` only on a trusted local machine, or configure through Hermes' MCP CLI if supported.
- Restart Hermes or run `/reload-mcp` after changing MCP config.

## What this repo should add beyond official MCP

### 1. Hermes setup and verification

- Add copy/paste Hermes MCP config examples.
- Add `hermes mcp add/test/list` instructions.
- Add clean setup validation steps:
  - Node.js present.
  - `npx -y @thetalabs/on-demand-api-mcp --help` or startup check works.
  - Hermes can discover tools after `/reload-mcp` or restart.
  - `list_services` works without leaking secrets.

### 2. Controller/project APIs

Keep and expand Python helper coverage for APIs not handled by the official on-demand MCP server:

- VM catalog.
- Standard/custom deployment templates.
- Deployment list/create/delete.
- Org balance.
- Future start/stop helpers.

### 3. Dedicated OpenAI-compatible endpoint workflows

Keep improving dedicated endpoint support:

- `/v1/models` readiness polling.
- `/v1/chat/completions` test calls.
- DeepSeek R1 Distill Qwen 7B validated path.
- Long warm-up/cost warnings.
- Persistent/pre-warmed endpoint guidance.

### 4. Safe disposable deployment validator

Add one high-value workflow tool/command:

1. Read balance before.
2. Create deployment with generated Basic Auth.
3. Poll readiness with template-specific probes.
4. Run one small smoke request.
5. Delete deployment in `finally`.
6. Verify deployment list cleanup.
7. Read balance after and report delta.

### 5. Hermes-native plugin/toolset wrapper

After the official MCP path is documented and tested, consider a Hermes plugin that exposes direct tools like:

- `theta_capabilities`
- `theta_controller_vm_types`
- `theta_controller_list_deployments`
- `theta_controller_create_deployment`
- `theta_controller_delete_deployment`
- `theta_dedicated_models`
- `theta_dedicated_chat`
- `theta_disposable_validate`

This plugin should use check functions so tools only appear when needed env vars are configured.

## Security requirements

- Do not print raw Theta credentials.
- Redact secret-like fields recursively.
- Require `--yes` or explicit confirmation for mutating controller operations.
- Prefer `THETA_DRY_RUN=1` for first runs.
- Enforce `https://` for dedicated endpoint auth.
- Keep official MCP token scoped to the MCP subprocess env only.
- Document that paid inference and GPU deployments can consume balance.
